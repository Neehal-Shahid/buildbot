# Complete Product Audit – User Experience, User Flow, Business Logic & Real-World Usage Review

You are acting as:

* Senior Product Manager
* Senior UX Designer
* Senior UI Designer
* Senior SaaS Founder
* Senior QA Engineer
* Senior Customer Success Manager

Your job is NOT to review code quality.

Your job is to review the ENTIRE PRODUCT as if you were a real customer paying for it.

Think like a real user.

Think like a first-time visitor.

Think like a confused customer.

Think like a customer who wants to cancel.

Think like a customer who made a mistake.

Think like a customer who doesn't understand technical terms.

Think like a customer on mobile.

Think like a customer who never reads instructions.

---

# CRITICAL RULES

DO NOT review code architecture.

DO NOT focus on coding style.

DO NOT focus on refactoring.

Focus on:

* Product problems
* User problems
* UX problems
* Navigation problems
* Missing features
* Business logic issues
* Trust issues
* Conversion issues
* Retention issues
* User confusion
* Customer frustration

Evaluate the project as a REAL PRODUCT.

---

# Phase 1 – Understand The Product

First determine:

1. What this product does.
2. Who the target user is.
3. What problem it solves.
4. What the user's goal is.
5. What success looks like for the user.

Explain the product journey.

---

# Phase 2 – First-Time User Audit

Imagine a brand-new user.

Review:

* Landing page
* Signup flow
* Login flow
* Verification flow
* Dashboard access
* Initial setup

Answer:

* Is it obvious what the product does?
* Is the value proposition clear?
* Is signup friction too high?
* Are users likely to abandon?
* Is anything confusing?
* Is anything missing?

List every issue.

---

# Phase 3 – Onboarding Audit

Review onboarding.

Identify:

* Missing instructions
* Missing guidance
* Missing tooltips
* Missing onboarding steps
* Missing progress indicators
* Missing examples
* Missing empty states

Determine whether a new user could successfully use the product without contacting support.

---

# Phase 4 – Navigation Audit

Review navigation structure.

Check:

* Menus
* Dashboard
* Settings
* Account management
* Billing areas
* Widget management
* Reports

Determine:

* What feels hidden?
* What is difficult to find?
* What takes too many clicks?
* What feels inconsistent?

Suggest improvements.

---

# Phase 5 – User Flow Audit

Review every major workflow.

For each workflow identify:

Start
→ Steps
→ End Goal

Then identify:

* Friction points
* Confusing points
* Unnecessary steps
* Dead ends
* Missing feedback

Examples:

Signup
Login
Email Verification
Widget Creation
Widget Publishing
Widget Management
Settings
Account Updates
Subscription Management

Review all major flows.

---

# Phase 6 – Mobile Experience Audit

Review the product from a mobile user's perspective.

Check:

* Navigation
* Forms
* Buttons
* Modals
* Tables
* Widget setup
* Settings pages

Identify:

* Frustrations
* Accessibility issues
* Hidden elements
* Overflow issues
* Touch target issues

---

# Phase 7 – Trust & Credibility Audit

Evaluate whether users trust the product.

Check:

* Error messages
* Success messages
* Email communications
* Verification flows
* Branding consistency
* Security indicators
* Privacy indicators

Identify anything that may reduce trust.

---

# Phase 8 – User Error Handling

Assume users make mistakes.

Check:

* Wrong email
* Expired verification
* Expired OTP
* Invalid widget
* Duplicate widget
* Network failure
* API failure
* Empty forms

Determine:

* What happens?
* Is recovery easy?
* Are messages helpful?

Identify missing safeguards.

---

# Phase 9 – Customer Support Audit

Determine whether users can easily get help.

Check:

* Contact methods
* FAQs
* Help sections
* Troubleshooting

Identify support gaps.

---

# Phase 10 – Business Logic Audit

Ignore code.

Review business logic.

Ask:

* Does the workflow make sense?
* Are there unnecessary restrictions?
* Are users blocked unnecessarily?
* Are there loopholes?
* Can users get stuck?
* Can users accidentally break something?

Identify logic flaws.

---

# Phase 11 – Retention Audit

Determine why users might stop using the product.

Look for:

* Lack of engagement
* Lack of feedback
* Lack of value visibility
* Lack of progress indicators
* Lack of reminders
* Lack of success milestones

Identify retention risks.

---

# Phase 12 – Conversion Audit

Review the product like a SaaS founder.

Ask:

* What would prevent signup?
* What would prevent upgrade?
* What would prevent activation?
* What would reduce trust?

Identify conversion bottlenecks.

---

# Phase 13 – Accessibility Audit

Review:

* Contrast
* Readability
* Font sizes
* Keyboard usage
* Screen reader compatibility
* Focus states
* Error states

Identify accessibility issues.

---

# Phase 14 – Security Perception Audit

Even if technically secure:

Would users FEEL secure?

Review:

* Password flows
* Verification flows
* Account settings
* Session management

Identify trust concerns.

---

# Phase 15 – Missing Features Audit

Think like a mature SaaS product.

Identify:

* Features users would reasonably expect
* Missing account controls
* Missing notifications
* Missing status indicators
* Missing logs
* Missing activity history
* Missing confirmations
* Missing safeguards

Only suggest features with clear user value.

Avoid feature bloat.

* Business Impact
